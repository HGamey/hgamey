      新建灰层会话模板

      只填入下方任务参数，不立即启动。模板不修改已有会话；功能支持以 producer 的任务返回为准，旧版本可能拒绝新参数。

      四臂 refbench 模板

      A/B 先核查实际无层，作为无层对照。C/D 加载改写层，分别核对应用开关关闭与开启的预期。这里只采集固定 refbench 的原件与自报，不代表游戏 FPS 或功耗收益。

      固定目标 io.github.hgamey.refbench。模板只填参数；提交后沿任务记录查看结果与失败原件，功能支持以 producer 返回为准。

      输入工件清单 可选，JSON

      同节点最多 32 份文件，每份不超过 8 MiB，总计不超过 32 MiB。清单需包含 schema、node_id、files、bindings、cwd；源文件缺失或变化会使准备失败，不会自动等待或重跑。

      argv 可用 @in/ 加 target；显式 JSON pointer 绑定生成独立文件并保留源 JSON。脚本不做文本替换，可使用 PF_JOB_IN 或 cwd=input 下的相对路径。

      运行时间预算 可选

      仅从命令实际启动后计时，上传、排队和输入准备不计入。升级停止在 SIGINT 后 15 秒可发 TERM，再 15 秒可发 KILL，可能打断恢复。到期是停止请求期限，不保证任务已经结束或设备已经恢复。

      日志与磁盘软阈值 可选

      启动前核查一次；运行中最多每秒观察一次，达到阈值后请求停止，期间仍可能写入。日志长度是同一日志文件的逻辑长度，空间是相关文件系统的共享可用量。这不是硬配额，不截断或删除原件，也不保证设备已恢复。

      数值越高，在满足资源、设备 lease 与原全域排队约束的候选中越先执行；同级保持提交顺序。不会抢占运行中的任务，恢复任务也可声明优先级。

      宿主调度声明 可选

      未显式声明时省略字段，新调度器按 CPU 1 / GPU 0 / I/O 0 兼容记账。0 表示未预留，不表示程序不使用该资源。与作业执行名额、独占资源键、设备 lease 分开。

      提交结果不确定时，保留原请求 ID 并先查询。本页保存原 ID、节点、设备绑定、预算、宿主 slots 与优先级声明，不保存完整参数或掌舵密码；刷新后可继续查询。
